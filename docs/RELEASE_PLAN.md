## 제한 확인

이전 실제 오류: HTTP 402, `api-deployments-young-hobby-team-24h`, `retryAfter: 86400`. 이는 한국시간 자정 초기화를 확인한 증거가 아니다. `https://vercel.com/docs/limits` 및 제공된 재시도 안내를 기준으로 확인한다. 읽기 전용 상태 조회와 배포 요청을 구분하고, 할당량을 확인하려고 새 배포 요청을 반복하지 않는다. 알려진 재시도 시간 전에는 재요청하지 않는다.

## 현재 배포 전 차단 사항

2026-11-05 환경변수 이름·대상만 다시 확인한 결과 `DATABASE_URL`, `SOC_DATA_BACKEND`, `SOC_PREVIEW_ISOLATED`가 없다. 생산/검수용 Blob 토큰이 공유된 기존 구성이며 비밀값은 문서에 저장하지 않았다.

1. SOC 전용 PostgreSQL 연결, 기존 24개 기록 백업의 정합성·SOC ID 유지 이관 및 복구 리허설이 필요하다. 기존 데이터·계정은 삭제하지 않는다.
2. 미이관 운영 데이터에 검수 데이터를 섞지 않는다. 검수 환경을 쓴다면 별도 DB와 `SOC_PREVIEW_ISOLATED=true`가 필요하다. 플래그만 설정해서 공유 저장소 차단을 우회하지 않는다.
3. 최신 PR SHA의 CI가 성공해야 한다. API·동시성·저장 실패·복구 시험과 Chromium 모바일/PC 검증 결과를 확인한다.
4. 원격 DB의 연결·스키마·복구 확인 전에는 main에 병합하지 않는다. 새 코드는 production에서 PostgreSQL 없이 회원가입·신청·운영 변경을 503으로 차단한다. 조회와 로그아웃은 유지한다.

## 조건 충족 시 한 번 배포

현재 PR HEAD, main HEAD, CI와 배포 기록을 새로 조회한다. 이미 동일 SHA가 배포됐으면 새로 만들지 말고 그 결과를 검수한다. PR의 변경 전체가 준비되고 위 차단 사항이 해소됐을 때 한 번 병합하여 기존 Git 연동 배포를 사용한다. Git 배포가 생성되고 있는 동안 추가 수동 배포를 만들지 않는다. 제한으로 생성되지 않았다면 오류의 다음 시각 이후 같은 최종 커밋으로 한 번 재시도한다. 실패 시 본문·SHA·오류·재시도 조건을 기록하고 연속 재시도하지 않는다.

READY만으로 성공 처리하지 않는다. 실제 health SHA, 응답 캐시, 로그인/권한, 저장·조회, 경기·증명 흐름을 검증한 뒤 주소를 대조한다. 미검증 배포를 이전 대표주소에 연결하지 않는다. 유료 전환·외부 계약·실거래·고객 문자·도메인 구매는 별도 승인 범위다.

## 실운영 판단

현재는 운영 승인 전이다. 이메일 확인·분실 비밀번호 복구, 추가인증의 운영 검수, 보호자 확인 절차, 개인정보 운영주체·보유기간, 규정 승인, 후원/훈련 계약·예산은 아직 연결 또는 확정이 필요하다. 수납은 대표 지시에 따라 무통장입금이며 PG는 현재 배포·운영의 필수조건이 아니다. 실제 입금계좌·기한·안내문 설정, 신고→은행내역 대조→확인→참가권→환불 장부 검수를 수행한다. 배포 제한 해제와 이 요건을 혼동하지 않는다.


추가인증 환경변수 `SOC_MFA_ENCRYPTION_KEY`는 production/preview에 각각 등록되었다. 값을 재생성·출력하지 않는다. 배포 전 이름·대상과 실제 설정 유효성을 확인하고 DB 복구 시 암호화 키 보존도 검증한다. 회계용 migration 002를 포함해 `scripts/migrate.mjs`로 순서대로 적용한다. 현재 코드는 계좌번호를 하드코딩하지 않으며 운영관리자가 검증한 계좌를 관리 화면에서 설정한다.
