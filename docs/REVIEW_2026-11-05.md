## 권고 방향

1. 첫 실운영 범위는 무료회원·승인 아카데미·단일 대회의 신청/무통장입금/현장운영/결과·증명으로 고정한다. 후원·해외훈련·상품은 각 서비스의 계약과 운영 기능을 갖춘 뒤 별도 공개한다.
2. 수납 화면은 입금대기·신고접수·확인완료·환불검토·환불기록을 분리한다. 다음 개선의 우선순위는 은행내역 파일 대조, 합산입금 배분, 입금기한 예외 처리다. 자동 은행연동을 하지 않아도 수납 누락을 줄일 수 있다.
3. 대표 화면은 확인 입금·실제 환불·순입금·미대조 건수와 운영 차단사항부터 보여준다. 매출, 현금, 계약금액, 미수금, 지원예산을 섞어 하나의 실적으로 표시하지 않는다.
4. 첫 대회 리허설은 동일 시간대 접수와 계체·여러 매트·결과 정정·장애복구를 포함한다. 자동시험 통과는 실제 행사 운영 승인과 구분한다.

## 시험 증거와 한계

`npm run validate`는 API/브라우저 스크립트 문법과 격리 자동시험을 실행한다. SQL은 로컬 PGlite와 CI PostgreSQL 17을 구분하고, `npm run test:browser`는 Chromium 390×844 / 1365×900에서 실제 입력·클릭을 수행한다. 무통장입금·환불·MFA 시험도 합성 계정·시험 은행정보만 사용하며 실제 송금·고객 발송은 하지 않는다.

최신 실행 결과와 커밋은 PR #2/CI 기록에서 확인한다. 현재 운영 DB 이관·최종 배포·실제 장치·실은행 대조까지 통과한 상태가 아니므로 **실회원 모집 및 실대회 운영 개시 승인은 보류**한다.
